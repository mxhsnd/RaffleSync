# 活动名单 JSON 数据源设计

## 背景

项目当前在 `data.js` 中通过姓氏、名字数组随机生成 5 个学院各 600 人的测试名单。用户希望这次先使用 `数据参考/360032384_按文本_又至毕业别离季，歌声献礼致青春。歌曲串烧投票_366_366.xlsx` 中提取出的班级和姓名作为临时测试名单，但数据不能继续写死在 JS 逻辑里。

这份名单应按“活动数据”处理：现在是测试数据，下一次可以直接替换为真实活动名单。用户希望名单存在一个单独 JSON 文件中，方便人工直接修改、删除或替换；系统只读取 JSON 中的信息。

## 目标

- 从 Excel 表格中提取“1、您的班级：”和“3、您的姓名：”。
- 不保存手机号、IP、投票内容等无关或敏感字段。
- 新增一个单独的活动名单 JSON 文件，作为抽奖系统唯一名单数据源。
- 保留当前系统的 5 个学院设置，支持普通抽奖和学院特殊礼物抽奖继续工作。
- 为每条临时记录补充稳定的临时 `studentId`，用于现有去重、重抽和展示逻辑。
- 后续真实活动只需要修改或替换 JSON 文件，不需要改抽奖逻辑。

## 数据来源与清洗

数据来源文件为：

`数据参考/360032384_按文本_又至毕业别离季，歌声献礼致青春。歌曲串烧投票_366_366.xlsx`

处理规则：

1. 读取第一张工作表。
2. 定位并提取两列：
   - 班级：`1、您的班级：`
   - 姓名：`3、您的姓名：`
3. 去掉班级或姓名为空的记录。
4. 排除明显无效的测试/误填记录：班级和姓名都缺乏有效文本语义的记录，例如班级为 `1` 且姓名为 `1`。
5. 单字姓名保留，因为可能是真实填写。
6. 输出仅包含抽奖需要字段：`college`、`className`、`name`、`studentId`。
7. `isDrawn` 不写入 JSON。它是运行时状态，由页面加载后在内存中补充为 `false`。

## JSON 文件结构

新增活动数据文件：

`event-data.json`

结构如下：

```json
{
  "eventName": "毕业晚会抽奖临时测试数据",
  "colleges": [
    {
      "name": "安全科学与工程学院（应急管理学院）",
      "shortName": "安全科学与工程学院"
    }
  ],
  "students": [
    {
      "college": "软件学院（人工智能学院）",
      "className": "软件22-16",
      "name": "陈作国",
      "studentId": "TEMP0001"
    }
  ]
}
```

设计原则：

- JSON 只保存活动原始名单信息和学院列表。
- JSON 不保存抽奖状态，避免刷新后把临时运行状态误当成活动名单。
- 用户可以直接编辑 `event-data.json`，删除某个学生或替换整份名单。
- `studentId` 在测试数据中使用 `TEMP0001`、`TEMP0002` 等临时编号；真实数据如有学号，可以直接填真实学号。

## 学院归类规则

系统继续使用当前 5 个学院：

- `安全科学与工程学院（应急管理学院）`
- `工商管理学院`
- `电气与控制工程学院`
- `电子与信息工程学院`
- `软件学院（人工智能学院）`

班级前缀归类如下：

| 班级前缀 | 归属学院 |
| --- | --- |
| 软件、网络、数据、智能、计算 | 软件学院（人工智能学院） |
| 电气、电网、自动、自动化、智控、测控 | 电气与控制工程学院 |
| 电信、电子、通信 | 电子与信息工程学院 |
| 工商、工管、会计、信管、国贸、金融、商务、营销 | 工商管理学院 |
| 其他无法识别前缀 | 安全科学与工程学院（应急管理学院） |

选择这个归类方式是因为用户确认“就是现在系统里的五大院，先分，不对再改”。无法从班级前缀可靠判断到前四类的记录，先统一放入安全科学与工程学院，保证数据都能参与抽奖并保持 5 个学院结构稳定。

## 前端加载方式

当前项目是纯静态前端。为了让系统真正读取 JSON，需要把数据加载改成异步流程：

1. 页面启动时通过 `fetch('event-data.json')` 读取活动数据。
2. 读取成功后：
   - `colleges` 使用 JSON 中的学院列表。
   - `studentData` 使用 JSON 中的学生列表，并给每条记录补充运行时字段 `isDrawn: false`。
3. 控制台和大屏逻辑只在数据加载完成后初始化。
4. 如果 JSON 读取失败或格式不正确，在页面上显示明确错误，不再回退到随机假数据。

注意：使用 `fetch` 读取本地 JSON 时，需要通过本地静态服务访问页面，例如项目 README 中的：

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000/admin.html` 和 `http://localhost:8000/index.html`。直接双击 HTML 用 `file://` 打开可能无法读取 JSON。

## 代码边界

- `event-data.json`：保存活动名单和学院列表，是用户后续主要修改的文件。
- `data.js`：改为数据加载模块，负责读取 JSON、校验结构，并暴露现有代码需要的 `colleges` 和 `studentData`。
- `control.js`：需要等待数据加载完成后再初始化控制台、渲染学院按钮、执行抽奖。
- `display.js`：如果只展示控制台发送的中奖数据，原则上不需要直接读取名单；但页面仍应等待基础数据模块完成，避免脚本顺序问题。
- `admin.html` / `index.html`：保留脚本拆分结构，必要时调整脚本加载方式以支持异步初始化。

## 错误处理

数据加载失败时：

- 控制台显示错误状态，例如“活动名单 JSON 加载失败，请检查 event-data.json 或使用本地服务器打开页面”。
- 禁用抽奖按钮，避免空名单抽奖。
- 浏览器控制台输出具体错误，方便排查 JSON 格式问题。

数据格式校验至少覆盖：

- `colleges` 必须是非空数组。
- `students` 必须是非空数组。
- 每个学生必须有 `college`、`className`、`name`、`studentId`。
- `studentId` 不能重复。
- 学生的 `college` 必须存在于 `colleges` 列表中。

## 受影响组件

- 新增：`event-data.json`
- 修改：`data.js`
- 修改：`control.js`
- 可选修改：`display.js`
- 可选修改：`admin.html`，将默认状态文案从“已加载 3000 名测试学生”改为加载后显示实际人数或通用文案。

## 验证方式

实现后检查：

1. `data.js` 不再包含随机姓名生成数组和 `Array.from({ length: 600 })`。
2. `event-data.json` 中只包含活动数据，不包含手机号、IP、投票选项等字段。
3. 系统启动后实际名单来自 `event-data.json`。
4. 所有学生记录都有完整字段：`college`、`className`、`name`、`studentId`。
5. 所有 `college` 值都属于当前 5 个学院之一。
6. `studentId` 没有重复。
7. 打开 `admin.html` 后学院特殊礼物抽奖仍显示 5 个学院。
8. 普通抽奖和学院抽奖能从 JSON 名单中抽出学生，展示姓名和班级。
9. 临时移除或破坏 `event-data.json` 时，页面给出可理解的错误提示，而不是静默使用旧假数据。

## 非目标

- 不引入后端服务。
- 不在浏览器运行时解析 Excel。
- 不保存手机号、IP、投票选择等字段。
- 不改变抽奖算法、去重逻辑或大屏动画。
- 不继续保留随机假名单作为回退数据。
